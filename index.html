什么是 NLPM？

NLPM (Natural-Language Programming Manager) 是自然语言产物的验证、打分与测试套件。它将自然语言制品（Prompt、技能、智能体、规范）视为可执行、可被 Lint 的程序代码。 就像 ESLint 校验 JavaScript，Ruff 校验 Python 一样，NLPM 运用 50 条军规与 100 分制体系，对驱动 AI 行为的 Markdown 文件进行严格的语法与质量门禁审计。

🎯 核心能力 (What it does)

  • 清单盘点: 自动扫描并识别工作区内的全部自然语言资产
  • 质量打分: 基于 50 条军规进行 100 分制确定性质量评分
  • 跨组件一致性检查: 验证 Manifest 与磁盘文件的物理同步状态
  • 自动修复与安全: 自动执行修复并扫描越狱/提示词注入风险
  • NL-TDD 测试: 针对自然语言特性的测试驱动开发(TDD)工作流

🧮 100 分制质量标尺

  • 90-100 (Excellent): 满分标杆，直接用于生产就绪
  • 80-89 (Good): 质量优秀，仅有轻微优化空间
  • 70-79 (Adequate): 达到及格门槛，建议修复反模式
  • < 70 (Rewrite): 违反关键红线，存在严重幻觉风险，必须重写

CLI 工具

纯 Python 静态分析器。秒级校验 Frontmatter 闭合、必填字段、kebab-case 命名一致性。包含单体技能回退（check_standalone 本地补丁）。

CI 徽章

📜 50 条军规核心法则检索手册 (The 50 Rules)

自然语言编程的宪章与 SSOT 风格指南，点击可随时查阅各条款与正反例

R01 通用法则
严禁使用缺乏量化标准的模糊定词
"适当"、"合理"、"高质量"、"必要时"等词汇毫无约束力，必须替换为可量化指标。扣分: -2/处 (上限-20)。
❌ 错误："使用适当的错误处理。"
✅ 正确："从所有 API handler 返回 Result<T, AppError>。"
R02 通用法则
每一行提示词都必须赚回其 Token 价值
上下文窗口是有限的黄金资产。如果一行内容不会改变大模型的行为，立即删除它。
❌ 错误："你是一个非常聪明、乐于助人且专业的助手。"
✅ 正确："你是一名 Rust 异步并发专家，专攻 Tokio 运行时。"
R03 通用法则
正面指导优于消极禁止 (Pink Elephant Effect)
使用“使用 X”而非“不要使用 Y”。禁止性表述容易引发大模型的注意力固着。
❌ 错误："千万不要在循环中写异步 await。"
✅ 正确："使用 Promise.all() 进行批量并发请求。"
R04 技能规范
Description 是触发器而非摘要
至少包含 3 个匹配真实用户提问的具体动词短语，确保按需精准唤醒。
❌ 错误："description: 很有用的 React 辅助工具。"
✅ 正确："description: 当调试 React 重渲染、修复 hook 依赖数组时触发。"
R05 技能规范
单文件严格控制在 500 行以内
超过 500 行会导致上下文膨胀。应拆分为有明确作用域的子技能并通过引用组合。
❌ 错误：一个包含 1500 行的庞大巨石 SKILL.md。
✅ 正确：拆分为核心规范 + references/ 附属文档按需读取。
R09 智能体规范
必须提供至少 2 个完整 <example> 块
每个示例必须包含：上下文 (Context) + 用户意图 + 助手结构化响应。
❌ 错误：只有抽象的任务描述，零具体样例。
✅ 正确：提供多场景 Few-shot 对话示例块。
R11 智能体规范
工具权限严格遵循最小特权原则
只读类 Agent 严禁配置写入/运行工具。权限越界属于高危安全隐患。
❌ 错误：只读审查 Agent 拥有 write_to_file 权限。
✅ 正确：审查 Agent 仅分配 view_file / grep 工具。
R14 斜杠命令
多步骤工作流必须显式数字编号
散落在自然语言段落中的流程极易遗漏，必须使用 1. 2. 3. 严格时序定义。
❌ 错误：“首先做A，接着做B，然后还要做C。”
✅ 正确：“步骤 1：扫描；步骤 2：校验；步骤 3：提交。”
